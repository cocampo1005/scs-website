# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Marketing/portfolio site for Solid Code Solutions LLC (https://solidcodesolutionsllc.com). Client-side React 19 SPA built with Vite 6, Tailwind CSS v4, React Router v7, and Framer Motion. TypeScript (strict, `allowJs` while the remaining `.jsx` files are migrated: the 3D scenes, SOLID exhibit, legal pages and lightbox). Vitest + Testing Library unit/component tests and Playwright e2e tests. The contact form posts to a small PHP endpoint (`server/`, PHPMailer over SMTP); local development needs PHP 8.2+ and Composer.

## Commands

- `npm run dev` — Vite dev server with HMR (proxies `/api/contact` to `npm run dev:api`)
- `npm run dev:api` — PHP built-in server for the contact endpoint on port 8787; creates a dev `server/config.php` that writes messages to `server/var/outbox/` instead of sending
- `npm run build` — production build to `dist/`
- `npm run preview` — serve the production build locally
- `npm run lint` — ESLint (flat config in `eslint.config.js`, react-hooks + react-refresh + typescript-eslint)
- `npm run typecheck` — `tsc` (strict, `tsconfig.json`)
- `npm test` — Vitest unit/component tests (`src/**/*.test.{js,jsx,ts,tsx}`, jsdom)
- `npm run test:php` — PHPUnit tests for `server/` (run `composer install` in `server/` first)
- `npm run e2e` — Playwright against `vite preview` on port 4173, using the installed Chrome (`e2e/`)
- `npm run check` — lint, typecheck, test, test:php, build, e2e
- `npm run build:release` — production build behind `scripts/check-release.mjs` (endpoint, `.htaccess` `/api` rules, locked server deps, no EmailJS)
- `npm run package:release -- --server-dir=<abs path>` — builds `release/site-*.zip`, `release/server-*.zip` and `release/htaccess.production` (`--target=staging` also exists); releases go directly to production, see `docs/deployment.md`
- `BASE_URL=https://solidcodesolutionsllc.com npx playwright test` — the e2e suite against the live site (contact tests are mocked; nothing is sent)

## Architecture

- **Design**: SCS 2.0 "Precision × Cinematic" (approved canvas and decisions in `docs/design-review.md`). Dark only; bentos of tiles on a 12/6/2-column grid (desktop/tablet/phone); an engineering grid motif; one feature tile per section.
- **Routing**: `src/App.tsx` defines all routes inside the shared shell (`components/layout/SiteHeader` with the mobile menu, `SiteFooter`). Pages: `/`, `/services` (anchors `#custom`, `#automation`, `#modernization`, `#websites`), `/work`, `/work/:slug` (case studies), `/about`, `/contact`, `/privacy`, `/terms`; unknown paths and unknown slugs render `NotFound`. Old `/projects?case=<key>` links redirect: 301 in `public/.htaccess`, `ProjectsRedirect` client-side.
- **Content is data-driven and typed** (`src/content/`, model in `types.ts`): `work.ts` (`CASE_STUDIES` with `slug`, `legacyKeys`, `kind: software | website`, plus `OTHER_PROJECTS`), `screenshots.ts` (alt text required), `services.ts` (`SERVICES` by tier, process, FAQs), `site.ts` (contact details, nav, socials). Adding a case study: images under `src/assets/projects/`, an entry in `CASE_STUDIES`, and its slug in `public/sitemap.xml` and the `^work/(…)` rule in `public/.htaccess`.
- **UI primitives** (`src/components/ui/`): `Button`/`LinkButton`, `Container`/`Section`/`SectionHeading`/`Eyebrow`, `Bento`/`Tile` (`variant: default | feature | open`, responsive `span`/`rows`; a `to` makes it a link with a pointer spotlight), `TagList`, `GridBackdrop`, `Accordion`; `layout/PageHeader` for inner pages; `ContactBand` closes most pages.
- **Deep links**: `Contact` reads `?intent=start-similar&project=<slug>&title=…` to prefill the form (`buildStartSimilarLink` in `src/utils/similarProjectLinks.ts`). `useScrollToHash` scrolls to `#hash`; the fixed header offset comes from CSS `scroll-padding-top`.
- **SEO**: each page renders `<SEO>` (title/description/canonical/OG/Twitter tags) with `<JsonLd>` children. They rely on React 19's automatic hoisting into `<head>`; no react-helmet. URLs use `ORIGIN` from `src/constants/seo.ts`.
- **Homepage hero**: `components/hero/HomeHero` (state in `hooks/useHomeHero.ts`, a tested reducer). Copy on the left (stacked below 1024px), the puzzle stage on the right; the canvas spans the hero and is transparent, so the grid and `CircuitLayer` (SVG/CSS circuit sequence, about 2.2 s) show behind it. A deliberate solve (drag or "Place it for me") plays the circuit and lights `StoryStrip` 1.9 s later; reduced motion shows the still circuit. The solve is stored in `sessionStorage` (`scs:hero-solved`), read after mount; a restored session starts assembled with no sequence. "Replay the puzzle" clears it and remounts the scene (`replayKey`) in the same WebGL context.
- **Hero puzzle (React Three Fiber)**: `HomeHero` lazy-loads `src/components/hero3d/HeroPuzzleCanvas`, which renders the drag-to-complete cube puzzle from the local GLB `public/models/scs-hero-puzzle.glb` (exported from the original Spline scene; reference files in `docs/references/spline-hero-section/`). Transforms, camera and light values live in `hero3d/puzzleConfig.js` in Spline units. `PuzzleScene` owns the drag state machine (`idle → dragging → snapping → completed`) and calls `onSolved`. "Place it for me" sets `skipped`, which the scene animates like a drop; `restored` starts it assembled. The hero renders it with `shadowFloor` (a transparent floor that only takes shadows) and no bubbles. `StageFraming` zooms and offsets the camera on both axes so the puzzle sits in the stage element. Only touches that start on the logo cube are captured. Without WebGL, on a scene error (`SceneBoundary`) or on context loss, a static poster (`assets/images/hero-puzzle-solved.webp`) replaces the canvas. Shared helpers: `src/three/webgl.js`, `src/components/SceneBoundary.jsx`. Cube pieces and the logo cube share one parent group so the solved cube spins and floats as a unit. The canvas renders with `frameloop="always"` (idle/solved float), `"demand"` under reduced motion, and `"never"` when off-screen or the tab is hidden.
- **About page SOLID puzzle (React Three Fiber)**: `SolidPuzzle` (state via `useSolidPuzzle`) lazy-loads `src/components/solid3d/SolidPuzzleCanvas`. Visitors drag seven pieces into shape-matched outlines to rebuild the 6x4 wall. Pieces come from `public/models/scs-solid-puzzle.glb`, trimmed from the Spline export in `docs/references/spline-tetris-solid-interaction/` by `node scripts/extract-solid-puzzle-model.mjs`. Each piece's GLB node transform *is* its target. Outlines are traced from the mesh (`solidSilhouette.js`). Copy, start arrangements and tuning live in `src/constants/solidPuzzleData.js`. Layouts: `wide` (≥768px) uses fixed seeded arrangements around the wall; `tall` (phones) shelf-packs unplaced pieces into a tray under the wall that re-packs and shrinks the stage as pieces are placed (the scene reports the stage height via `onStageChange`). Info is HTML, with one open piece at a time (`activeInfoId`): `SolidInfoPanel` in a column beside the board at ≥1024px, `SolidInfoSheet` (a bottom sheet portalled to `<body>`, minimized while the board is touched) below that. While the logo piece is open, the GLB's Logo Cube pops out of its slot inside the board canvas (`LogoReveal`); there is no second WebGL context. Spline is no longer a dependency.
- **SEO files**: `index.html` carries static fallback title/description/OG tags (`data-static-seo`, removed in `main.jsx`). `public/robots.txt`, `public/sitemap.xml` and `public/.htaccess` must list the routes in `src/routes.ts` (a test enforces it). OG image: `public/og-default.jpg`.
- **Content rules**: no unsourced percentages or multipliers (`src/__tests__/content.test.ts`, which also rejects drafting placeholders such as `[Confirm …]`); case studies use `outcomes`. Legal pages use fixed dates from `src/constants/legal.js`.
- **Contact form**: client validation in `src/utils/contactValidation.ts`; `src/utils/contactApi.ts` posts JSON to same-origin `/api/contact` and maps responses (`validation`, `rate_limited`, `unavailable`, `timeout`, `network`). The optional "tools you use" field is appended to the message. The Ads conversion fires only on `{ok:true}`. Phone input uses `react-phone-input-2` with overrides in `src/styles/phone-input.css`.
- **Contact endpoint (PHP)**: `public/api/contact.php` is a thin front controller that loads the private server folder (`SCS_SERVER_DIR` via `SetEnv`, else `../../scs-server`) and returns 503 if that folder is under the document root. `server/` (namespace `Scs\Contact`) holds `bootstrap.php`, `ContactHandler` (method → attempt limit (every POST) → type/size/origin/JSON → honeypot/timing → validation → spam screen → send limit → send; both limits in SQLite via `RateLimiter`), `ContactValidator` (mirrors the JS rules and messages; keep them in sync), `RateLimiter`, `ContactLog` (no personal data), and `Mail/SmtpTransport` (PHPMailer) or `Mail/FileTransport` (dev). Secrets live only in the server folder's `config.php` (gitignored; template `server/config.example.php`). Design and response shapes: `docs/contact-smtp-plan.md`. `server/tools/hostinger-probe.php` is a one-off host capability check.

## Styling

Tailwind v4 via the `@tailwindcss/vite` plugin; there is no `tailwind.config.js`. Design tokens live in the `@theme` block of `src/index.css`, which replaces Tailwind's default palette (`--color-*: initial`): surfaces `bg`, `bg-raised`, `surface`, `surface-deep`, `line`, `line-strong`; text `ink`, `ink-soft`, `ink-muted`, `ink-subtle`, `link`; accents `accent`, `violet`, `violet-strong`, `fuchsia`, `fuchsia-strong`, `focus`, `signal` (cube and circuit only); status `danger`, `success`; fonts `font-display` (Space Grotesk), `font-sans` (Work Sans), `font-mono` (JetBrains Mono), `font-logo` (Rajdhani, self-hosted in `public/fonts/`). Component classes there: `.display`, `.label`, `.text-gradient` (once per page), `.tile`/`.tile-feature`/`.tile-open`/`.tile-interactive`, `.grid-motif`, `.tag`, `.screenshot`. Use tokens, never raw hex. Icons come from `lucide-react` and `@phosphor-icons/react`.
